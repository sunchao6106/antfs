# S3 网关设计

S3 兼容网关(`crates/s3`,二进制 `antfs-s3`)。与 `antfs-frontend` 同层,内嵌 `antfs-router` SDK 做 blob I/O,外接 PostgreSQL / MySQL 做名字映射(bucket + key → blobId)。网关本身**无持久状态**,可 N 实例水平扩容。

## 架构

```
S3 客户端 ── S3 API ──▶ antfs-s3 (axum)
                          ├── auth/sigv4.rs     SigV4 签名验证
                          ├── auth/middleware.rs axum 鉴权中间件
                          ├── handlers/
                          │   ├── object.rs     PutObject / GetObject / HeadObject / DeleteObject
                          │   ├── multipart.rs  Create / Upload / Complete / Abort / ListParts / ListUploads
                          │   ├── bucket.rs     CreateBucket / DeleteBucket / HeadBucket / ListBuckets / ListObjectsV2
                          │   ├── batch.rs      DeleteObjects
                          │   └── admin.rs      凭证 CRUD（operator token 保护）
                          ├── metastore/
                          │   ├── mod.rs        MetaStore trait + connect()
                          │   ├── pg.rs         PostgreSQL 实现 (sqlx)
                          │   └── mysql.rs      MySQL 实现 (sqlx)
                          ├── xml.rs            S3 XML 请求/响应序列化
                          ├── error.rs          S3 错误码 → HTTP status + XML body
                          └── router SDK        antfs-router（号段缓存 + W 多数派写 + R=1 读）
                              └── antfs 存储集群
```

写路径：S3 PutObject → 小 body `put_auto_with_ttl` / 大 body 暂存+`put_file_with_ttl` → blob 落盘 → MetaStore INSERT `(bucket, key, version) → blob_id`。
读路径：S3 GetObject → MetaStore SELECT 最新 READY 版本 → `router.get(&blob_id)` → 流式返回。
Multipart：每片独立 blob,CompleteMultipartUpload 只写 manifest（`parts_manifest` JSON），GetObject 时依次 `router.get` 各片拼接流式返回。

## S3 操作映射

| S3 操作 | HTTP | 路径 | MetaStore | Router SDK | 说明 |
|---|---|---|---|---|---|
| PutObject | PUT | `/{bucket}/{key}` | `put_object` | `put_auto_with_ttl` / `put_file_with_ttl` | ≤ `inline_body_max` 走内存 |
| GetObject | GET | `/{bucket}/{key}` | `get_object` | `router.get` | multipart 对象逐片流式拼接 |
| HeadObject | HEAD | `/{bucket}/{key}` | `get_object` | — | 只返回元数据 headers |
| DeleteObject | DELETE | `/{bucket}/{key}` | `delete_object` | `router.delete` | soft-delete + blob 删除 |
| DeleteObjects | POST | `/{bucket}?delete` | `delete_objects` | 逐个 `router.delete` | XML 请求/响应 |
| ListObjectsV2 | GET | `/{bucket}?list-type=2` | `list_objects` | — | prefix + delimiter + pagination |
| CreateBucket | PUT | `/{bucket}` | `create_bucket` | — | 同 owner 幂等 |
| DeleteBucket | DELETE | `/{bucket}` | `delete_bucket` | — | 需空桶 |
| HeadBucket | HEAD | `/{bucket}` | `head_bucket` | — | |
| ListBuckets | GET | `/` | `list_buckets` | — | 按 owner 过滤 |
| CreateMultipartUpload | POST | `/{bucket}/{key}?uploads` | `create_multipart` | — | 生成 upload_id |

**对象元数据(乙路线,与 blob 引擎隔离)**:每个对象的 `Content-Type` 与用户自定义 `x-amz-meta-*` 键值**只存 MetaStore**(`named_objects.content_type/user_meta` 列,`multipart_uploads` 持有会话期值,Complete 时随行落库),blob 字节不含任何元数据。GET/HEAD 从 MetaStore 行回吐这些头。边界(采集时校验):

- `x-amz-meta-*` 总量(Σ 键+值 UTF-8 字节)超 **2048** → `MetadataTooLarge`(400,S3 语义官方上限,具名常量非配置);
- `Content-Type` 头长超 **256**(存储列宽 `VARCHAR(256)`)→ `InvalidArgument`(400;而非落库时 500);
- PUT/CreateMultipart **不带** `Content-Type` → 存储**默认值 `binary/octet-stream`**(AWS 同语义);
- 历史行(本改动前写入,`content_type` 为 NULL)GET 不回吐该头,与新写行为有明示差异,不做读取兜底。
| UploadPart | PUT | `/{bucket}/{key}?uploadId=X&partNumber=N` | `put_part` | `put_auto_with_ttl` | 每片独立 blob |
| CompleteMultipartUpload | POST | `/{bucket}/{key}?uploadId=X` | `complete_multipart` | — | 验证 ETag + 写 manifest |
| AbortMultipartUpload | DELETE | `/{bucket}/{key}?uploadId=X` | `abort_multipart` | 逐片 `router.delete` | |
| ListParts | GET | `/{bucket}/{key}?uploadId=X` | `list_parts` | — | 分页 |
| ListMultipartUploads | GET | `/{bucket}?uploads` | `list_multipart_uploads` | — | prefix + 分页 |

**multipart 会话原子性(所有权恰一次)**:同一 session 的 `put_part` / `complete_multipart` /
`abort_multipart` 在 MetaStore 内以**单一事务 + `multipart_uploads` 行锁(`SELECT … FOR
UPDATE`)全序化**(PG/InnoDB 同语义:锁读即 latest committed),封住三个泄漏口:①并发重传
同 part 时,被顶替的旧 blob **恰一次**交还给上传方墓碑化(不再因旧值过时快照漏掉中间
blob);② abort/complete 与 put 并发不再产生无主 part 行(先验后写插队窗口关闭);
③ **未列入 CompleteMultipartUpload manifest 的 part**(S3 语义:complete 即丢弃)经
`discarded_part_blobs` 上报、handler 与 `shadowed_blobs` 同路径回收。不变量由双方言内联
单测与 e2e 并发用例把守(`s3-multipart-lifecycle` 档)。留观:commit 后、回收下发前的
崩溃窗属既有类(`shadowed_blobs` 同窗),part 回收并入 GC 死点留后续 change。

管理接口（operator token 保护，不走 SigV4）：

| 操作 | HTTP | 路径 | 说明 |
|---|---|---|---|
| 创建凭证 | POST | `/admin/credentials` | 生成 access_key/secret_key |
| 删除凭证 | DELETE | `/admin/credentials/{access_key}` | 吊销 |
| 查询桶配额 | GET | `/admin/buckets/{bucket}/quota` | 返回 `{quota_bytes, used_bytes}` |
| 设置桶配额 | PUT | `/admin/buckets/{bucket}/quota` | body `{"quota_bytes": N}`,0 = 解除 |

## MetaStore Schema

5 张表，PostgreSQL 和 MySQL 双后端（`sqlx` + migrations）。

**buckets**

| 列 | 类型 | 约束 |
|---|---|---|
| name | VARCHAR(63) | PK |
| owner | VARCHAR(128) | NOT NULL |
| created_at | BIGINT | NOT NULL (epoch_ms) |
| quota_bytes | BIGINT | NOT NULL DEFAULT 0(0 = 不限;桶级存储配额)|
| used_bytes | BIGINT | NOT NULL DEFAULT 0(= 活行 size 之和,记账事务维护)|

**named_objects**（版本化 PK，支持覆盖写）

| 列 | 类型 | 约束 |
|---|---|---|
| bucket | VARCHAR(63) | PK 组合 |
| key | VARCHAR(1024) | PK 组合 |
| version | BIGINT | PK 组合 |
| blob_id | BINARY(8) / VARBINARY(8) | NOT NULL |
| state | SMALLINT | DEFAULT 1（0=IN_PROGRESS, 1=READY）|
| size | BIGINT | NOT NULL |
| etag | VARCHAR(128) | |
| content_type | VARCHAR(256) | |
| deleted_at | BIGINT | NULL = 存活 |
| created_at | BIGINT | NOT NULL |
| user_meta | TEXT | JSON map（x-amz-meta-*）|
| parts_manifest | TEXT | JSON（multipart 各片 blob_id + size）|

版本号 = `now_ns / 1000 + random % 1000`。GET 取 `WHERE state=1 AND deleted_at IS NULL ORDER BY version DESC LIMIT 1`。

**multipart_uploads**

| 列 | 类型 | 约束 |
|---|---|---|
| upload_id | VARCHAR(64) | PK |
| bucket | VARCHAR(63) | NOT NULL |
| key | VARCHAR(1024) | NOT NULL |
| created_at | BIGINT | NOT NULL |
| content_type | VARCHAR(256) | |
| user_meta | TEXT | |

**multipart_parts**

| 列 | 类型 | 约束 |
|---|---|---|
| upload_id | VARCHAR(64) | PK 组合 |
| part_number | INT | PK 组合 |
| blob_id | BINARY(8) / VARBINARY(8) | NOT NULL |
| size | BIGINT | NOT NULL |
| etag | VARCHAR(128) | NOT NULL |

**s3_credentials**

| 列 | 类型 | 约束 |
|---|---|---|
| access_key | VARCHAR(128) | PK |

**启动形态**:

- **独立二进制 `antfs-s3`**:读当前目录 `antfs-s3.toml`（顶层 `[s3]` 表；文件缺省时全部回落默认值），环境变量覆盖前缀 `AMBRY`（如 `AMBRY_S3__LISTEN_ADDR`、`AMBRY_S3__METASTORE__URL`），与 `antfs-frontend` 读 `frontend.toml`/`AMBRY` 前缀同型。启动顺序:connect MetaStore（含 `sqlx::migrate` 建表）→ connect router SDK → 起后台 GC 循环 → serve。
- **devcluster 内嵌**:`--s3-metastore-url` 给出时同进程起网关（默认 7500;缺省不起），配置由 devcluster 注入。
**后台 GC**(`[s3.gc]` 控制,默认开;详见 `openspec/changes/s3-gc/`):

- **软删/遮蔽行清理**:delete/overwrite 时行进入 `state=0, deleted_at=now`(blob **语义动作时即刻** `router.delete`,不欠账);GC 周期只清过保留期的行(blob 不再动 —— 死点前移是 spec 的现实修正,归档时以 MODIFIED 回写)。
- **孤儿 multipart 回收**:`created_at` 超过 `upload_ttl` 的未 Complete session,取件原子(PG `FOR UPDATE SKIP LOCKED` / MySQL `DELETE ORDER BY LIMIT`)后清 parts 行 + 逐片 `router.delete`(墓碑幂等)。
- **多实例安全**:取件原子 + 引擎墓碑重复删保护;每实例各自周期扫(无需 leader,取件互让)。
- 循环形态:每 `interval` 一轮、单轮上限 1000 行 / 100 session 背压;条目级失败记 `s3_gc_errors_total` 后继续,循环体永不 panic。

## 桶级存储配额

- **语义**:每桶 `buckets.quota_bytes`(0 = 不限)。`used_bytes` = 该桶 `state=1` 行 `size`
  之和;put/complete/delete 的**记账事务**同事务维护(GC purge 只删已扣过的行,不触碰)。
- **守卫(写入事务内,单语句原子)**:`used + 新写 − 遮蔽 ≤ quota` 才放行(**净增量口径**:
  覆盖大→小的写即刻放行);被拒 → **507** + XML code `QuotaExceeded`(带 bucket/quota/used),
  PUT 已写的 blob 按 s3-gc 死点模型**同请求 router.delete 墓碑**。守卫 0 行命中同时兜住
  「PUT 到不存在的桶 → 404 `NoSuchBucket`」(对齐真 S3)。
- **multipart**:parts 不计账;complete 时按 Σ part size 一次计入。被拒时 session/parts
  保留,**调大配额后原样重发 complete 即可重试**。
- **管理端点**(operator token,同 credentials 管理):`GET/PUT /admin/buckets/{bucket}/quota`
  (JSON `{bucket, quota_bytes, used_bytes}`;PUT 调小不追溯,只挡新写)。
- **竞态口径与上界**:守卫单语句条件 UPDATE(PG/InnoDB 短行锁)——并发抢最后余量恰一只
  成功(无超卖);MySQL 遮蔽两步圈定在极端并发下记账偏保守(change design.md 记档)。
  **InnoDB 锁序铁律(2026-10-15,MySQL 版特有,PG 版不涉)**:守卫的 `buckets` 行锁必须
  是记账事务的**第一把写锁**——若先触 `named_objects`(next-key + 插入意向锁)再守卫,
  并发同桶写会构成死锁环(1213;e2e race 用例实测 500/200,由 e2e MySQL 矩阵步捕获)。
  验证口径:双方言 e2e 矩阵净/脏双跑(`TEST_S3_DRIVER`)。**热桶吞吐上界** ≈ 单行
  UPDATE 串行率(千级 ops/s/桶),多桶互不影响。

## 多租户访问控制(私有桶 + public-read)

- **语义(私有桶,默认)**:每个 bucket-scoped 操作(对象读写删 / 批删 / 列举 / 桶
  HEAD/DELETE / multipart 全家族)要求**已验证签名**的请求且凭证 owner == 桶 owner,
  否则 403 `AccessDenied`(匿名同 403);桶不存在 → 404 `NoSuchBucket`(不存在判定
  优先于租户归属)。
- **凭证即租户**:`credentials.owner` 是唯一租户标识;一张凭证 = 一个租户(吊销凭证即
  驱逐)。同 owner 的多张凭证天然共享桶。
- **落点(私有面)**:server.rs 包装器层闸门(`require_bucket_owner`:`head_bucket`
  主键查询,亚毫秒池化);CreateBucket 不设闸(创建即按凭证 owner 认领名字,重名
  走既有 409 家族),ListBuckets 本就按 owner 过滤;`/admin/*` 与 `/metrics` 独立鉴权域
  不受影响。
- **presigned URL**:验签走签发凭证,主语判定与普通请求同。
- **public-read(桶级 canned ACL,`s3-canned-acl`)**:`buckets.acl ∈ {private,
  public-read}`(默认 private = 上述语义)。`public-read` 把**读面三件** —— GET/HEAD
  object 与 ListObjectsV2 —— 开放给任何人(匿名 / 任意签名租户 / owner);其余一切
  (写、删、批删、multipart 家族、ListMultipartUploads、桶 HEAD/DELETE、`?acl` 管理)
  仍 owner 独占。细则:
  - **主语**:`Principal = Signed | Anonymous`;匿名 = 请求上**完全没有**凭证(无
    `Authorization` 头且无预签 query);**验签失败绝不降级为匿名**(带坏凭证一律 403)。
  - **API**:`x-amz-acl: private | public-read` 于 CreateBucket 头(默认 private)与
    `PUT /{bucket}?acl`(owner-only,canned 头形式;AccessControlPolicy XML body 形式
    → **501 `NotImplemented`** 显式出界);`GET /{bucket}?acl`(owner-only)回
    AccessControlPolicy XML(public 时含 AllUsers READ grant);非法值 → 400
    `InvalidArgument`;切换对后续请求**即时生效**(无缓存,每请求一记 head_bucket)。
  - **尚未支持**(见矩阵):object 级 ACL / 桶策略 JSON / 跨 owner 授权(二期留评估)。

## 虚拟主机寻址(`s3.virtual_host_domain`,默认关)

- **机制(服务级管线)**:`build_app` 返回 `GatewayPipeline`(tower `Service`,`Clone`)——
  ① `/metrics`、`/admin/*` 公共面直发(不鉴权不改写,admin 自带 operator token 面);② **auth
  先按原 path + 原 Host 验签**(vhost 客户端签名 host 含桶、路径不含桶,与路径风格两种口径
  各自天然成立,验签零补偿),Principal 注入 extensions,失败即回绝;③ vhost 改写
  (`Host = {bucket}.{suffix}` → 路径前挂 `/{bucket}`,`:port` 剥离,非法桶标放行);④ Router
  分发,handler 的 `Extension<Principal>` 提取方式不变。
- **不做成路由层中间件(axum 机制课,裸 TCP 探针实证)**:`route_layer` 在**路由匹配之后**
  执行 —— 匹配与 Path 提取在改写前已定死,URI 改写改不了路由;改写必须发生在分发之前
  (服务级管线正是这个位置)。
- **Host 口径(字节级)**:签名的 host 串与实发 Host 头**逐字一致**即可(portless/portful 自洽
  皆可验证);夹具取 authority 形态(host:port)。**经典坑**(夹具实证):reqwest 的
  `.header()` 是 append 语义 —— HeaderMap 已带 host 后再 `.header(HOST, …)` 会出**双
  Host**,服务器按 SigV4 规范把多值头逗号连接 → 验签必败。
- **语义边界**:双风格并存(同集群同桶);TLS 泛证书 `*.s3.example.com` 只盖一层,桶名带
  点撞证书(S3 官方同款限制)。

## 流式分帧(`aws-chunked`,SigV4 STREAMING 家族)

真 AWS SDK/CLI 带体写默认 `Content-Encoding: aws-chunked` + `x-amz-content-sha256: STREAMING-*`;
解码前旧行为是「分帧字节原样入库 + Content-Length 误检 500」——真客户端写路径不可用,本轮封口。

- **申报面(验签前,不触库)**:三合法字面量 × `Content-Encoding: aws-chunked` ×
  `x-amz-decoded-content-length` × PUT/POST × 非 presigned 五条件强一致;撕裂(字面量缺配套、
  编码头无字面量、presigned 夹带、未知 `STREAMING-*` 变体)一律 400。非 STREAMING 摘要头照旧行。
- **风味与语法**:`STREAMING-AWS4-HMAC-SHA256-PAYLOAD`(块带签)/ `...-PAYLOAD-TRAILER`(块带签 + trailer 段)/
  `STREAMING-UNSIGNED-PAYLOAD-TRAILER`(块无签 + trailer 段);块 = `hex-size[;chunk-signature=64hex]CRLF data CRLF`,
  终块 0 尺寸(带签名风味终块也要签名),终块后仅容 CR/LF 空白;头行 1 KiB、trailer 8 KiB 上界。
- **块签名链**:种子 = Authorization 头请求签名;`STS_k = AWS4-HMAC-SHA256-PAYLOAD\\n{ts}\\n{scope}\\n{sig_{k-1}}\\n{sha256hex(data_k)}`;
  逐块常数时间比对;失配 403 且对象**不落库**;密钥链与请求头验签同一条。
- **管线序**:auth(产出 `AuthResolution{context, chunked}`)→ 包体 `AwsChunkedBody`(http_body::Body,
  `Error = S3Error` 直达语义)→ vhost 改写 → 分发;公共面不进此序。
- **错误回放(记档机制课)**:axum 错误链三层(包装 ×2 → 生源),须走 `source()` 链
  `downcast_ref::<S3Error>` 取回——顶层 downcast 摸不到;长舞(短于帧)400 分帧错,长申报 `IncompleteBody` 400,
  分帧垃圾 `InvalidArgument` 400,溯源失败落回既有 EntityTooLarge 宽语义(非分帧)。
- **明示不验证面**:trailer 逐行 debug 记档放行,`x-amz-checksum-*` 值与 trailer 签名不验证(信任面 =
  `UNSIGNED-PAYLOAD`;checksum 家族为后续方向承接)。非 STREAMING 十六进制 body 摘要不重算(同上)。
- **监控**:`s3_chunked_requests_total` / `s3_chunked_rejected_total{reason}`(framing/signature/length/oversize)。

## 拷贝与属性(CopyObject / GetObjectAttributes)

- **拷贝 = 复合原语闸门正交**:源按**公开读门**(owner 或 public-read,跨租户可拷公开桶)、
  终按既有 **PUT 写门**(桶 owner);无第三种权限概念。
- **执行**:单块源(≤ `max_body_bytes`)读→写→行(配额 507 弧同 put_object:拒 → 同请求墓碑);
  multipart 源 = **内部 session 逐 part 重建**(≤ 4 MiB/步,整 blob 绝不进内存 —— 红线);
  part 中途错弃置,孤儿 session 由既有 upload-TTL GC 兜;complete 的遮蔽/弃片回收全同线上面。
- **条件拷贝四头**:优先序 match > none-match > unmodified > modified;失配 `PreconditionFailed`(412);
  ETag 值剥引号比较;日期 rfc2822 解析,非法即 400。
- **元数据指令** `COPY`(默认)/ `REPLACE`;自拷贝 + COPY → `InvalidRequest`(400)——REPLACE 自拷 = 就地重写,合法。
- **501 面**:copy-source 带 `?versionId`(versioning 永久拒绝族);属性请求 `Checksum` / `ObjectParts`。
- **GetObjectAttributes**(`?attributes` + `x-amz-object-attributes` 头):可请求集
  {ETag / Checksum / ObjectParts / StorageClass / ObjectSize},未知 400;支持三属体式回
  显(ETag 裸值),响应头带引号 ETag + `Last-Modified`(RFC 7231);读门同 GET object。

## 关键决策



**D1：元数据后端 — 外接 PG/MySQL**。否决 master Raft（写路径瓶颈 + 不擅长前缀查询）、SQLite（单实例无法水平扩容）、独立 filer Raft（工程量过大）。用 `sqlx` 同时支持 PG 和 MySQL，编译期 SQL 检查 + async。

**D2：Schema — Ambry 启发的 5 表设计**。版本化主键 `(bucket, key, version)` 支持覆盖写；soft-delete（`deleted_at`）+ 后台 GC 清理。

**D3：Multipart — 元数据拼接，不做数据 stitch**。CompleteMultipartUpload 在 `named_objects` 写一行 `parts_manifest` JSON（各片 blob_id + size）；GetObject 时流式依次读各片拼接。否决 stitch 方案（引入 MAGIC 嗅探歧义）。

**D4：SigV4 — 自实现签名验证**。`aws-sigv4` crate 是客户端签名生成库，不是验证库。参考 SeaweedFS `auth_signature_v4.go`。凭证存 MetaStore `s3_credentials` 表，每请求查一次（连接池 < 1ms）。

**D5：路径风格路由为默认**。`/{bucket}/{key}` 路径风格；虚拟主机风格（`<bucket>.s3.domain`）2026-10-15 同日翻案落地(`s3.virtual_host_domain`,默认关;见「S3 功能支持矩阵」与「虚拟主机寻址」)。
