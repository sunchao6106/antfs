# S3 网关设计

S3 兼容网关(`crates/s3`,二进制 `antfs-s3`)。与 `antfs-frontend` 同层,内嵌 `antfs-router` SDK 做 blob I/O,外接 PostgreSQL / MySQL 做名字映射(bucket + key → blobId)。网关本身**无持久状态**,可 N 实例水平扩容。

## 架构

```
S3 客户端 ── S3 API ──▶ antfs-s3 (axum)
                          ├── auth/sigv4.rs     SigV4 签名验证
                          ├── auth/middleware.rs axum 鉴权中间件
                          ├── handlers/
                          │   ├── object.rs     PutObject / GetObject / HeadObject / DeleteObject
                          │   ├── multipart.rs  Create / Upload / Complete / Abort / ListParts / ListUploads
                          │   ├── bucket.rs     CreateBucket / DeleteBucket / HeadBucket / ListBuckets / ListObjectsV2
                          │   ├── batch.rs      DeleteObjects
                          │   └── admin.rs      凭证 CRUD（operator token 保护）
                          ├── metastore/
                          │   ├── mod.rs        MetaStore trait + connect()
                          │   ├── pg.rs         PostgreSQL 实现 (sqlx)
                          │   └── mysql.rs      MySQL 实现 (sqlx)
                          ├── xml.rs            S3 XML 请求/响应序列化
                          ├── error.rs          S3 错误码 → HTTP status + XML body
                          └── router SDK        antfs-router（号段缓存 + W 多数派写 + R=1 读）
                              └── antfs 存储集群
```

写路径：S3 PutObject → 小 body `put_auto_with_ttl` / 大 body 暂存+`put_file_with_ttl` → blob 落盘 → MetaStore INSERT `(bucket, key, version) → blob_id`。
读路径：S3 GetObject → MetaStore SELECT 最新 READY 版本 → `router.get(&blob_id)` → 流式返回。
Multipart：每片独立 blob,CompleteMultipartUpload 只写 manifest（`parts_manifest` JSON），GetObject 时依次 `router.get` 各片拼接流式返回。

## S3 操作映射

| S3 操作 | HTTP | 路径 | MetaStore | Router SDK | 说明 |
|---|---|---|---|---|---|
| PutObject | PUT | `/{bucket}/{key}` | `put_object` | `put_auto_with_ttl` / `put_file_with_ttl` | ≤ `inline_body_max` 走内存 |
| GetObject | GET | `/{bucket}/{key}` | `get_object` | `router.get` | multipart 对象逐片流式拼接 |
| HeadObject | HEAD | `/{bucket}/{key}` | `get_object` | — | 只返回元数据 headers |
| DeleteObject | DELETE | `/{bucket}/{key}` | `delete_object` | `router.delete` | soft-delete + blob 删除 |
| DeleteObjects | POST | `/{bucket}?delete` | `delete_objects` | 逐个 `router.delete` | XML 请求/响应 |
| ListObjectsV2 | GET | `/{bucket}?list-type=2` | `list_objects` | — | prefix + delimiter + pagination |
| CreateBucket | PUT | `/{bucket}` | `create_bucket` | — | 同 owner 幂等 |
| DeleteBucket | DELETE | `/{bucket}` | `delete_bucket` | — | 需空桶 |
| HeadBucket | HEAD | `/{bucket}` | `head_bucket` | — | |
| ListBuckets | GET | `/` | `list_buckets` | — | 按 owner 过滤 |
| CreateMultipartUpload | POST | `/{bucket}/{key}?uploads` | `create_multipart` | — | 生成 upload_id |

**对象元数据(乙路线,与 blob 引擎隔离)**:每个对象的 `Content-Type` 与用户自定义 `x-amz-meta-*` 键值**只存 MetaStore**(`named_objects.content_type/user_meta` 列,`multipart_uploads` 持有会话期值,Complete 时随行落库),blob 字节不含任何元数据。GET/HEAD 从 MetaStore 行回吐这些头。边界(采集时校验):

- `x-amz-meta-*` 总量(Σ 键+值 UTF-8 字节)超 **2048** → `MetadataTooLarge`(400,S3 语义官方上限,具名常量非配置);
- `Content-Type` 头长超 **256**(存储列宽 `VARCHAR(256)`)→ `InvalidArgument`(400;而非落库时 500);
- PUT/CreateMultipart **不带** `Content-Type` → 存储**默认值 `binary/octet-stream`**(AWS 同语义);
- 历史行(本改动前写入,`content_type` 为 NULL)GET 不回吐该头,与新写行为有明示差异,不做读取兜底。
| UploadPart | PUT | `/{bucket}/{key}?uploadId=X&partNumber=N` | `put_part` | `put_auto_with_ttl` | 每片独立 blob |
| CompleteMultipartUpload | POST | `/{bucket}/{key}?uploadId=X` | `complete_multipart` | — | 验证 ETag + 写 manifest |
| AbortMultipartUpload | DELETE | `/{bucket}/{key}?uploadId=X` | `abort_multipart` | 逐片 `router.delete` | |
| ListParts | GET | `/{bucket}/{key}?uploadId=X` | `list_parts` | — | 分页 |
| ListMultipartUploads | GET | `/{bucket}?uploads` | `list_multipart_uploads` | — | prefix + 分页 |

管理接口（operator token 保护，不走 SigV4）：

| 操作 | HTTP | 路径 | 说明 |
|---|---|---|---|
| 创建凭证 | POST | `/admin/credentials` | 生成 access_key/secret_key |
| 删除凭证 | DELETE | `/admin/credentials/{access_key}` | 吊销 |

## MetaStore Schema

5 张表，PostgreSQL 和 MySQL 双后端（`sqlx` + migrations）。

**buckets**

| 列 | 类型 | 约束 |
|---|---|---|
| name | VARCHAR(63) | PK |
| owner | VARCHAR(128) | NOT NULL |
| created_at | BIGINT | NOT NULL (epoch_ms) |

**named_objects**（版本化 PK，支持覆盖写）

| 列 | 类型 | 约束 |
|---|---|---|
| bucket | VARCHAR(63) | PK 组合 |
| key | VARCHAR(1024) | PK 组合 |
| version | BIGINT | PK 组合 |
| blob_id | BINARY(8) / VARBINARY(8) | NOT NULL |
| state | SMALLINT | DEFAULT 1（0=IN_PROGRESS, 1=READY）|
| size | BIGINT | NOT NULL |
| etag | VARCHAR(128) | |
| content_type | VARCHAR(256) | |
| deleted_at | BIGINT | NULL = 存活 |
| created_at | BIGINT | NOT NULL |
| user_meta | TEXT | JSON map（x-amz-meta-*）|
| parts_manifest | TEXT | JSON（multipart 各片 blob_id + size）|

版本号 = `now_ns / 1000 + random % 1000`。GET 取 `WHERE state=1 AND deleted_at IS NULL ORDER BY version DESC LIMIT 1`。

**multipart_uploads**

| 列 | 类型 | 约束 |
|---|---|---|
| upload_id | VARCHAR(64) | PK |
| bucket | VARCHAR(63) | NOT NULL |
| key | VARCHAR(1024) | NOT NULL |
| created_at | BIGINT | NOT NULL |
| content_type | VARCHAR(256) | |
| user_meta | TEXT | |

**multipart_parts**

| 列 | 类型 | 约束 |
|---|---|---|
| upload_id | VARCHAR(64) | PK 组合 |
| part_number | INT | PK 组合 |
| blob_id | BINARY(8) / VARBINARY(8) | NOT NULL |
| size | BIGINT | NOT NULL |
| etag | VARCHAR(128) | NOT NULL |

**s3_credentials**

| 列 | 类型 | 约束 |
|---|---|---|
| access_key | VARCHAR(128) | PK |
| secret_key | VARCHAR(256) | NOT NULL |
| owner | VARCHAR(128) | NOT NULL |
| created_at | BIGINT | NOT NULL |

**启动形态**:

- **独立二进制 `antfs-s3`**:读当前目录 `antfs-s3.toml`（顶层 `[s3]` 表；文件缺省时全部回落默认值），环境变量覆盖前缀 `AMBRY`（如 `AMBRY_S3__LISTEN_ADDR`、`AMBRY_S3__METASTORE__URL`），与 `antfs-frontend` 读 `frontend.toml`/`AMBRY` 前缀同型。启动顺序:connect MetaStore（含 `sqlx::migrate` 建表）→ connect router SDK → 起后台 GC 循环 → serve。
- **devcluster 内嵌**:`--s3-metastore-url` 给出时同进程起网关（默认 7500;缺省不起），配置由 devcluster 注入。
**后台 GC**(`[s3.gc]` 控制,默认开;详见 `openspec/changes/s3-gc/`):

- **软删/遮蔽行清理**:delete/overwrite 时行进入 `state=0, deleted_at=now`(blob **语义动作时即刻** `router.delete`,不欠账);GC 周期只清过保留期的行(blob 不再动 —— 死点前移是 spec 的现实修正,归档时以 MODIFIED 回写)。
- **孤儿 multipart 回收**:`created_at` 超过 `upload_ttl` 的未 Complete session,取件原子(PG `FOR UPDATE SKIP LOCKED` / MySQL `DELETE ORDER BY LIMIT`)后清 parts 行 + 逐片 `router.delete`(墓碑幂等)。
- **多实例安全**:取件原子 + 引擎墓碑重复删保护;每实例各自周期扫(无需 leader,取件互让)。
- 循环形态:每 `interval` 一轮、单轮上限 1000 行 / 100 session 背压;条目级失败记 `s3_gc_errors_total` 后继续,循环体永不 panic。

## 关键决策

**D1：元数据后端 — 外接 PG/MySQL**。否决 master Raft（写路径瓶颈 + 不擅长前缀查询）、SQLite（单实例无法水平扩容）、独立 filer Raft（工程量过大）。用 `sqlx` 同时支持 PG 和 MySQL，编译期 SQL 检查 + async。

**D2：Schema — Ambry 启发的 5 表设计**。版本化主键 `(bucket, key, version)` 支持覆盖写；soft-delete（`deleted_at`）+ 后台 GC 清理。

**D3：Multipart — 元数据拼接，不做数据 stitch**。CompleteMultipartUpload 在 `named_objects` 写一行 `parts_manifest` JSON（各片 blob_id + size）；GetObject 时流式依次读各片拼接。否决 stitch 方案（引入 MAGIC 嗅探歧义）。

**D4：SigV4 — 自实现签名验证**。`aws-sigv4` crate 是客户端签名生成库，不是验证库。参考 SeaweedFS `auth_signature_v4.go`。凭证存 MetaStore `s3_credentials` 表，每请求查一次（连接池 < 1ms）。

**D5：路径风格路由**。`/{bucket}/{key}` 路径风格；虚拟主机风格（`<bucket>.s3.endpoint`）留后续 change。

## 与参考系统对比

| 维度 | antfs S3 | SeaweedFS S3 | CubeFS S3 | Ambry |
|---|---|---|---|---|
| 名字映射 | 外接 PG/MySQL | 内嵌 filer（leveldb/redis） | 内嵌 metanode（Raft） | 外接 MySQL（named_blobs_v2） |
| 网关状态 | 无状态 | filer 有状态 | 无状态 | 无状态 |
| 多段上传 | 每片独立 blob + manifest JSON | 每片独立 chunk | 每片独立 extent | 不支持 S3 multipart |
| 鉴权 | SigV4 自实现 | SigV4 自实现 | SigV4 自实现 | IAM |
| 对象定位 | blobId（8 字节，自带 partition 编码） | fid（volume + needle） | inode + extent | blobId + partition |
| 冗余 | W 多数派副本 | EC / 副本可选 | 3 副本 / EC | W 多数派副本 |
