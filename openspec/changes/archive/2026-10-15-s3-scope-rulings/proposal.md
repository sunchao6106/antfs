# s3-scope-rulings —— S3 支持面永久裁决(versioning / 虚拟主机 / 计费 / 删除复活)

## Why

2026-10-15 用户对 S3 网关的支持面做产品方向拍板(非工程取舍,是否决):

1. **versioning 家族(桶版本化 / Object Lock / 多版本语义)——坚决不做,一直不做。**
   根因:与已锁 s3-gc 死点模型(删除/覆盖 = 旧 blob 立即墓碑、遮蔽同事务回收)正面冲突;
   versioned 语义要求保留旧版行 + 版本过期 GC 维度 = 推翻已锁语义。
2. **虚拟主机风格路由(`<bucket>.s3.endpoint`)——同上。** D5 路径风格为最终形态。
3. **多租户计费(用量计费 / 对账)——同上。** 桶级存储配额(硬限)已落地且保留——
   配额是管控闸,计费是对账系统,后者出 antfs 职责范围。
4. **删除复活(Undelete / 垃圾箱)——同上。** 死点模型直接推论:删除即终局;引擎
   `delete_is_irreversible` 不变量同源。

均**不是"暂缓"**——重开任一项须显式推翻对应裁定(另立 change)。

## What Changes

- `docs/design/s3.md`:新增「S3 功能支持矩阵」(✅ 支持 / ⛔ 永久拒绝 / 🅿 暂不支持 三档,
  并记录各项理由);「S3 操作映射」管理接口表补配额端点两行;D5 增补永久拒绝注;
  「后续方向」重排(下一轮 = 多租户 ACL、随后 B2 EC;移除已上线 GC 与被拒项)。
- `README.md` / `README_zh.md`:roadmap 与组件表同步(配额已上线、versioning/undelete/
  虚拟主机/计费永久出范围)。
- 零代码改动:全部为已实现行为的如实记录与产品边界宣告。

## Impact

- 文档:design/s3.md、README、README_zh。
- 契约:矩阵是 S3 兼容度的**权威声明**;外部使用者据此判断可用面。
- 后续:多租户 ACL 轮(用户已裁定顺序:ACL 先、EC 后)不受影响,照常立项。

## Non-goals

- 不实现 `?versioning` 等子资源的显式 NotImplemented 拒绝路由(现状即无支持面;
  需要时可作小加固项单独评估);
- 不动已落地的桶级配额(它属于"支持"档);
- 不影响 frontend(REST /blobs)层——裁决仅限 S3 网关。
